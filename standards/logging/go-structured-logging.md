# Go 结构化日志标准

本标准约束日志由采集端汇入集中检索系统的 Go 服务。日志只服务于三个目的，本标准的每条规则都由其中之一推出：

1. **可检索**：机器能稳定地查询、统计和告警；
2. **可定位**：人不复现问题也能判断发生了什么；
3. **无泄露**：日志不成为凭据与敏感数据的泄露途径。

参考实现：

- [`templates/go/logging/`](templates/go/logging/)：`logging` 包（logger 创建、line 格式 handler 及其契约测试、`logtest` 断言工具）；
- [`templates/filebeat-annotations.yaml`](templates/filebeat-annotations.yaml)：Filebeat 解析 line 格式的 Pod 注解；
- [`templates/event-catalog.md`](templates/event-catalog.md)：事件清单与字段词表模板。

规则分级、版本固定、例外与升级遵循[规范治理标准](../documentation/standard-governance.md)。

## 1. 项目采用声明

采用本标准的项目在 `ENGINEERING_STANDARDS.md` 中至少声明：

| 字段 | 要求 |
|---|---|
| 标准地址与版本 | 指向本文件，版本为 handbook 已发布的 Git tag，尚未发版时固定 commit SHA |
| 输出格式与采集链路 | 日志格式、采集器的解析规则及其所在位置 |
| 事件清单位置 | 本项目 event 与字段词表的现行规范来源 |

## 2. 强制规则

### 2.1 机器只依赖 `event` 与字段

- 每条日志带 `event`：稳定的英文事件码，`<领域>.<动作>`，如 `conn.closed`、`frame.publish_failed`。查询、告警与测试只基于 `event` 和字段。
- `msg` 是给人读的固定文案，不插入变量；变量一律作为字段输出。
- `event` 是对外契约：项目维护事件清单（event、等级、主要字段、枚举取值），新增或修改事件与清单在同一个 PR 中提交；改名或删除须同步修改依赖它的查询与告警。

### 2.2 同名字段同义同型

- 同名字段在所有事件中类型与含义一致，由项目的字段词表定义。否则检索系统的字段映射冲突，查询结果不可信。
- 带单位的数值在字段名中写明单位（`dur_ms`），原始字节与报文以字符串输出（`*_hex`、`payload`），不展开为嵌套对象。

### 2.3 等级表示是否需要人处理

| 等级 | 判定标准 |
|---|---|
| ERROR | 需要人工介入，或数据已丢失 |
| WARN | 输入异常或降级，服务可自愈，需关注频率 |
| INFO | 生命周期事件，以及有诊断或运营价值的工作单元摘要 |
| DEBUG | 调试细节，仍须遵守脱敏与大小限制 |

- 预期内的事件（服务停止、空闲超时、对端正常断开）不得记为 WARN/ERROR；未真正成功的操作不得记成功日志。两者都会使告警失真。
- 同一事件因原因不同而需要不同等级时，先把原因归类为枚举值（如 `reason`），再由枚举值决定等级。

### 2.4 关闭 DEBUG 时问题仍可定位

- WARN/ERROR 日志自带定位所需的现场数据；需要人工补录时，优先记录受控补偿存储的引用、业务主键与校验摘要。只有经字段白名单与脱敏策略允许的报文才可输出；无泄露要求优先于现场完整性。日志不得充当唯一的数据恢复或审计存储。
- 上下文在工作单元的边界通过 `With` 绑定（如连接、请求、已识别的业务主键），该单元内的日志自动携带；只绑定已确定的事实，不为日志提前解析输入。
- 一个错误只在处理它的那一层记录一次，下层返回带上下文的错误。
- 项目声明 goroutine 的 panic 处理策略。仅在能隔离失败、清理资源并保证后续状态一致的边界使用 `recover`，以 ERROR 记录 panic、堆栈与脱敏上下文；否则保留进程失败与重启行为，避免工作协程静默退出后服务继续报告健康。

### 2.5 不输出敏感信息

- 禁止输出凭据、令牌，以及可能包含它们的客户端对象或连接选项；该要求覆盖所有等级、错误文本、panic 值、堆栈附带上下文及第三方日志。
- 需要输出配置结构体时实现 `slog.LogValuer`，只列出可输出的字段并打码敏感项，并有单元测试断言明文不出现。

### 2.6 所有日志经过同一出口

- 只使用 `log/slog`，logger 由项目的 `logging` 包按配置创建。第三方日志允许保留其原有文案与格式；采集端必须标识来源并保留无法解析的原文，不得伪造业务 `event`。第三方库的日志通过 `slog.SetDefault`（标准库 `log`）或 `slog.NewLogLogger` 接入，不得丢弃其告警与错误。
- logger 由 `main` 创建并显式传入业务代码，业务代码不使用 `slog.Default()`，使测试能注入 logger 并断言日志。

### 2.7 输出格式与采集规则是一份契约

- 日志写入 stdout，一条日志恒为一行（含堆栈），并发写入不交错。
- 采集端解析规则随应用一起发布，应用中有复现该规则的测试，二者在同一个 PR 中修改。
- 应用字段放在独立命名空间（如 `app.*`），避免与检索系统的保留字段冲突导致整条日志被拒绝写入。

### 2.8 日志成本与故障边界

- 项目声明单条日志大小上限、截断方式、保留期与访问权限。截断保留 `event`、关联主键与截断标识；报文和堆栈不得无限增长。
- 高频日志声明采样或限流策略，保留被抑制数量，避免把采样后的数量当作业务总量。精确计数使用指标或业务数据。
- 项目声明输出阻塞、磁盘或采集失败时的处理方式，并验证不产生无限队列；诊断日志失败是否允许影响业务，由业务可用性要求决定。法定或业务审计记录另行定义持久化与交付保证。

## 3. 测试

新增或修改 WARN/ERROR 事件、等级判定与打码时必须有单元测试。断言使用 `logtest` 按 `event` 校验等级与字段，不匹配 `msg`。

## 4. 项目必须决定的策略

- 输出格式（参考实现的 `line` 或 `json`）及 `msg` 的语言；
- 字段词表：业务主键的名称、类型与编码；
- 高频 WARN 是否采样或限流，以及告警阈值；
- 报文的可输出字段白名单、脱敏与补偿存储策略；
- panic 隔离、日志大小、保留期、采样与输出失败策略。

## 5. 评审与 CI

CI 检查业务代码不导入标准库 `log`、不调用 `slog.Default()`（`main` 与 `logging` 包除外），可用 golangci-lint 的 `depguard`、`forbidigo` 实现。

评审确认：

- [ ] 新增日志带 `event`，`msg` 不含变量，事件清单已同步；
- [ ] 等级符合 2.3，WARN/ERROR 自带现场数据；
- [ ] 无敏感信息输出；
- [ ] 修改输出格式时，采集解析规则与契约测试同步修改。
